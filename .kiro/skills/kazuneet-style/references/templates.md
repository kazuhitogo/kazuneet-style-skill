# 媒体別テンプレート

`<...>` は差し替える。検証していない内容は書かない。

## A. Qiita「試してみた」型 (最頻出)

```markdown
# <サービス名> の <機能名> を試す

<一次情報 URL>

<出ました。 / 〜が GA しました。 / 〜が来ましたね。>

今北産業すると、

* <前提・課題> しても
* <何ができるか> する仕組みが
* できたよ

## やってみる

Doc を見ながらいきます。

<該当ドキュメント URL>

<やることを 1〜2 文>

```bash
<コマンド>
```
```json:出力
<出力>
```

<出力から読み取れることを 2〜3 文。独り言ツッコミを括弧で 1 つ>

## 結果

<条件を先に書く>。<結果を表か箇条書きで>。

<予想と違った点、失敗した点>

## まとめ

<要点 2〜4 文>

以上、<雑検証 / とりあえずやってみた>でした。
```

## B. Qiita 連載型 (例: ①②③ シリーズ)

- 冒頭: `前回は、「<前回の要約を 1 文>」でした。` と前回リンク。
- 本文: 1 記事 1 テーマ。読者が疑問に思うことは `②エンジニアが①を読んで浮かぶQA` のように、別記事の Q&A にする。
- 末尾: 次回予告と、シリーズの `記事一覧` 見出し (リンクの箇条書き)。予告したのにやらなかった場合は、追記で正直に書く (`(追記: やりませんでした)`)。

## C. Qiita 小ネタ・検証型 (短い)

```markdown
# <〜する最も短いコード / 〜を知りたくないか…？>

<背景の悩みを 2〜3 文>

<そんなとき〜できるのか、というお話>

## コード

```python:main.py
<コード>
```

<動作の説明を 2〜3 文。どこで何を保持し、何をキャンセルするか>

## まとめ

<結論を 1〜2 文。ネタの決め台詞で締めてもよい>
```

## D. 【翻訳】型

```markdown
# 【翻訳】<原題>

<原文 URL>

<公開日> に出た "<原題>" を翻訳しました。<なぜ読む価値があるか 1 文>。

(翻訳本文: 原文の見出し構造を保つ)

## 翻訳注

自分が翻訳しながら読んだので、表記揺れは多々あると思いますが以下を意識しています。直して欲しいところがあったらコメントいただければ、できる範囲で修正します。

- <用語の訳し方>

## 翻訳外 (任意)

<読んだ感想や、手元で気をつけるべきこと>
```

## E. 注意書きが要る記事

過激な入力例を使う検証 (例: Guardrails のコンテンツフィルター) では、冒頭に置く。

```markdown
:::note warn
記事の都合上、紳士淑女にふさわしくない表現が多々現れます。**苦手な方はここでブラウザバックすることを強く推奨します。**
:::
```

## F. Zenn 型 (少し長め)

```markdown
<イベント参加記事なら: 本ブログは <イベント名> (<ハッシュタグ>) の第 N 日目です。>

## <サービス名> is Generally Available

出ました。

<URL>

## <サービス名> 今北産業（個人のお気持ち）

- <課題>
- <解決の方向>
- <だから何をしようぜ>

## この記事は？

<何を 3 分や 1 ページで試すか>。<番外編があれば一言>。

## 前提

- <必要なツール> (早くもチートのかほり)
- <権限や認証> は、ちゃんと設定されてるよね？

## やってみよう

### <手順 1>
...

## まとめ
```

## G. builders.flash 型 (公式ウェブマガジン)

```markdown
## <日常のボケ話で始まる見出し>

<肩書きのボケ付き自己紹介>の呉です。Builder の皆様いかがおすごしでしょうか。
<季節や家庭の小話を 1〜2 段落>

ということで、<日常の悩み> を IT で解決しました。今回は <成果物> を紹介します。この記事を読めば <読者ができること> ができるようになります。

## デモ動画
<入力は何と何だけで、何ができたか。注釈は ※ で添える>

## ご注意
本記事で紹介する AWS サービスを起動する際には、料金がかかります。(定型の免責)

## <題材> ってなに？
<勝手に命名した場合は「これは私が勝手に命名したものですが」と断る>

## <技術> とは？
<公式説明の引用 + 「私にはピンとこなかったのですが」からの自分の言葉での言い換え>

## 結局何をしたのか？
<経緯を 2〜3 文でまとめ直す。「〜というお話です」で締める>

## 環境作成
## 実装
## 動かしてみる
## まとめ
```

共著・対談を入れる場合は、`プロローグ (作者対談)` として 呉「」/ 相手「」の掛け合いを冒頭に置く。掛け合いは元ネタ付きのツッコミにする (例: 「質問を質問で返すなあーっ !!」)。
