# 記事の種類別テンプレート

`<...>` は差し替える。検証していない内容は書かない。迷ったら A を使う。

## A. 試してみた型 (基本)

```markdown
# <サービス名> の <機能名> を試す

<一次情報 URL>

<出ました。 / 〜が GA しました。 / 〜が来ましたね。>

今北産業すると、

* <前提・課題> しても
* <何ができるか> する仕組みが
* できたよ

## やってみる

Doc を見ながらいきます。

<該当ドキュメント URL>

<やることを 1〜2 文>

```bash
<コマンド>
```
```json:出力
<出力>
```

<出力から読み取れることを 2〜3 文。独り言ツッコミを括弧で 1 つ>

## 結果

<条件を先に書く>。<結果を表か箇条書きで>。

<予想と違った点、失敗した点>

## まとめ

<要点 2〜4 文>

以上、<雑検証 / とりあえずやってみた>でした。
```

## B. 日常ネタ導入型 (動機をネタにしたいとき)

A の冒頭を、次のように差し替える。

```markdown
## <日常のボケ話で始まる見出し>

<自分の立場を軽くボケて紹介> です。みなさま、いかがおすごしでしょうか。
<季節や家庭の小話を 1〜2 段落>

ということで、<日常の悩み> を IT で解決しました。今回は <成果物> を紹介します。この記事を読めば <読者ができること> ができるようになります。

## デモ

<入力は何と何だけで、何ができたか。注釈は ※ で添える>

## <題材> ってなに？

<勝手に命名した場合は「これは私が勝手に命名したものですが」と断る>

## <技術> とは？

<公式説明の引用 + 「私にはピンとこなかったのですが」からの自分の言葉での言い換え>

## 結局何をしたのか？

<経緯を 2〜3 文でまとめ直す。「〜というお話です」で締める>
```

以降は A の「やってみる」以下と同じ。料金が発生するなら、手順の前に注意を書く。

## C. 連載型 (①②③ シリーズ)

- 冒頭: `前回は、「<前回の要約を 1 文>」でした。` と前回リンク。
- 本文: 1 記事 1 テーマ。読者が疑問に思うことは、`②エンジニアが①を読んで浮かぶQA` のように、別記事の Q&A にする。
- 末尾: 次回予告と、`記事一覧` 見出し (リンクの箇条書き)。予告したのにやらなかった場合は、追記で正直に書く (`(追記: やりませんでした)`)。

## D. 小ネタ・検証型 (短い)

```markdown
# <〜する最も短いコード / 〜を知りたくないか…？>

<背景の悩みを 2〜3 文>

<そんなとき〜できるのか、というお話>

## コード

```python:main.py
<コード>
```

<動作の説明を 2〜3 文。どこで何を保持し、何をするか>

## まとめ

<結論を 1〜2 文。ネタの決め台詞で締めてもよい>
```

## E. 翻訳型

```markdown
# 【翻訳】<原題>

<原文 URL>

<公開日> に出た "<原題>" を翻訳しました。<なぜ読む価値があるか 1 文>。

(翻訳本文: 原文の見出し構造を保つ)

## 翻訳注

自分が翻訳しながら読んだので、表記揺れは多々あると思いますが以下を意識しています。直して欲しいところがあったらコメントいただければ、できる範囲で修正します。

- <用語の訳し方>

## 翻訳外 (任意)

<読んだ感想や、手元で気をつけるべきこと>
```

## F. 手順を最短で示す型 (「3 分で動かす」など)

```markdown
<イベント参加なら、冒頭にイベント名とハッシュタグを 1 行>

## <サービス名> is Generally Available

出ました。

<URL>

## <サービス名> 今北産業（個人のお気持ち）

- <課題>
- <解決の方向>
- <だから何をしようぜ>

## この記事は？

<何を 3 分や 1 ページで試すか>。<番外編があれば一言>。

## 前提

- <必要なツール> (早くもチートのかほり)
- <権限や認証> は、ちゃんと設定されてるよね？

## やってみよう

### <手順 1>
...

## まとめ
```

## G. 注意書きが要る記事

過激な入力例を使う検証では、冒頭に置く。

```markdown
:::note warn
記事の都合上、紳士淑女にふさわしくない表現が多々現れます。**苦手な方はここでブラウザバックすることを強く推奨します。**
:::
```

## H. 掛け合い導入 (共著・対談)

冒頭に `プロローグ (作者対談)` を置き、呉「」/ 相手「」の掛け合いにする。掛け合いは元ネタ付きのツッコミにする (例: 「質問を質問で返すなあーっ !!」)。
